# ToyotaWaits.ca Master Plan V3.2 — Execution Roadmap (Sprints 5 & 6)

## Global Constraints & Operating Safeguards
1. **Core Tracker Isolation**: Zero modifications to existing wait-time calculations, public CSV endpoints, submission form handlers, or legacy migrations.
2. **Epistemic Honesty**: Always present listings as "Advertised - availability unconfirmed" or "Incoming availability unconfirmed". Never infer cancellations or confirmed availability without explicit source evidence.
3. **No WAF/Auth Bypasses**: Respect rate limits, user agent disclosures, and coverage limitations.
4. **Test Integrity**: Full test suite (`npm test`) must pass with 100% success rate on every sprint completion.

---

## Sprint 5: UI Integration & Search/Filter Components
- **Branch**: `feature/v3.2-sprint5-ui-integration` (off `feature/v3.2-sprint4-outbox-worker`)
- **Objectives**:
  1. Create isolated discovery UI components in `components/discovery/`:
     - `VehicleListingCard.tsx`: Display model, trim, price breakdown (with "Price not verified" if fees are missing), exact evidence status badge, last-checked timestamp, and direct canonical dealer link.
     - `InventoryFilterBar.tsx`: Facet by Model (Sienna, RAV4 Hybrid), Status (Advertised vs Incoming), Region/Dealer, and Price range.
     - `CoverageDisclosureBanner.tsx`: Transparently explain that inventory is currently monitoring validated Lower Mainland dealers (Convertus platform) and show documented coverage limitations (Granville, OpenRoad).
  2. Implement a dedicated route at `app/inventory/page.tsx` (or `pages/inventory.tsx` matching current Next.js structure) wrapped in a feature flag (`ENABLE_INVENTORY_DISCOVERY`).
  3. Ensure mobile responsiveness, accessible ARIA labels, and explicit disclaimer that availability must be confirmed directly with the dealer.
  4. Write component tests under `tests/discovery/ui-components.test.ts`.

---

## Sprint 6: Private Trial Runner & Audit Telemetry (Gate 2 Readiness)
- **Branch**: `feature/v3.2-sprint6-trial-telemetry` (off `feature/v3.2-sprint5-ui-integration`)
- **Objectives**:
  1. Build an automated cron/worker runner (`lib/discovery/runners/scheduled-poll.ts`):
     - Executes scheduled sweeps at a conservative interval (e.g. 12-hour cadence).
     - Handles errors with backoff and logs source health telemetry to a `source_health_logs` table.
  2. Implement an audit reporter (`scripts/discovery/generate-trial-report.ts`):
     - Generates metrics meeting Gate 2 Private Trial requirements:
       * Source uptime / check success rate (>= 95% target).
       * Observation count, unique vehicles observed, and status transition counts.
       * Stale listing percentage.
       * Traceability score (100% having dealer, link, evidence label, and check time).
  3. Add npm run script: `"trial:report": "tsx scripts/discovery/generate-trial-report.ts"`.
  4. Write telemetry and runner tests under `tests/discovery/scheduled-poll.test.ts`.
